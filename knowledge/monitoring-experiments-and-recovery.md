# 监控、实验、内容维护与恢复

## 监控体系

| 频率 | 监控 | 典型告警 |
|---|---|---|
| 实时/每日 | uptime、5xx、robots、noindex、canonical、sitemap、部署 | 核心目录不可用或索引指令变化 |
| 每周 | GSC 点击/展示、索引、抓取、CWV、排名分布 | 同比/环比异常且超过正常波动 |
| 每月 | 页面类型、品牌/非品牌、市场、收入、内容衰退 | 某模板或主题持续下降 |
| 每季度 | 主题组合、架构、链接、竞品、技术债 | 资源重新分配 |

告警同时看绝对值、百分比、季节性和数据延迟。设置站点自身基线，不使用所有网站通用的 10% 阈值。

## SEO 实验

大站可做模板级 split test，小站可做准实验：

1. 写清假设、目标指标、护栏、页面集合、实施日期和最小观察窗。
2. 选择相似 test/control 组，控制季节、品牌活动、库存和迁站。
3. 一次尽量改一个主要变量；记录所有部署。
4. 关注 GSC clicks/impressions、业务转化与索引，不只排名工具。
5. 不因前几天波动提前停止；结论包含不确定性和可迁移边界。

不要对同一 URL 向用户和搜索引擎显示不同实验内容。A/B URL 使用正确 canonical，测试结束清理变体和重定向。

## 内容衰退与更新

按页面类型比较滚动周期、同比和查询变化。下降可能来自需求、SERP、竞争、意图、索引、库存或追踪，不是看到日期旧就重写。

更新动作：纠正事实、补原创证据、改善任务完成、合并重叠、更新产品/媒体/内链、删除过期部分。只有实质更新才改 `dateModified` 或页面可见更新时间。

## 流量下降诊断

顺序：

1. 验证分析和 GSC 数据、过滤、时区、同意模式。
2. 切分品牌/非品牌、目录、页面、查询、国家、设备、搜索类型。
3. 检查部署、robots/noindex/canonical/redirect/status、DNS/CDN、手动处置和安全问题。
4. 对比索引、crawl、日志、CWV、SERP 和竞争变化。
5. 检查季节性、促销、库存、品牌需求和算法更新。
6. 找受影响模式，修根因；不要全站盲目删内容或改日期。

## 核心更新后的恢复

Google 更新不是一个“处罚按钮”。用受影响页面做诚实的内容/质量/专业性/体验自评，优先大幅改善最弱模板；避免为了恢复而堆字、批量 noindex、买链接或制造新的低价值内容。恢复可能需重新抓取、重新评估和后续系统更新，记录长期变化。

## 变更与知识日志

每项记录：日期、URL/模板、假设、负责人、代码/内容变更、指标基线、观察窗、结果、决定、后续。把失败实验保留在仓库，防止团队重复踩坑。
