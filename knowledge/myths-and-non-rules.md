# 常见误区与非规则

| 说法 | 实战结论 | 分类 |
|---|---|---|
| 每页只能有一个 H1 | 多个 H1 不是 Google 排名违规；一个清晰主标题是推荐的语义、无障碍与团队规范 | 建议 / 项目门禁 |
| meta description 必须 150-160 字符 | 没有固定字符硬限制；170 字符不是硬错误。看独特性、关键信息、摘要展示和 CTR | 建议 |
| FAQ schema 每页必须加 | 并非 SEO 必须；仅在页面有可见 FAQ 且类型适用时添加。有效标记也不保证富结果 | 资格 |
| `llms.txt` 是 GEO 必备 | `llms.txt` 是实验性约定，不是 Google/Bing/OpenAI 搜索收录或排名要求 | 实验 |
| 所有外链都应 nofollow | 不要全站 nofollow。正常可信编辑引用保持普通链接；付费 `sponsored`、UGC `ugc`、不愿背书时 `nofollow` | 要求 / 建议 |
| 内容至少 300/1000/2000 字 | 没有最佳字数。写到用户任务完成，不注水 | 非规则 |
| 关键词密度 1%-3% | 没有官方最佳密度，刻意重复可能构成关键词堆砌 | 非规则 |
| LSI 关键词能提升排名 | “LSI 关键词”不是 Google SEO 机制；自然覆盖相关实体、问题和概念即可 | 非规则 |
| E-E-A-T 是一个排名因子/分数 | E-E-A-T 是质量评估框架，不是单一排名因子；Trust 最关键，YMYL 更严格 | 评估框架 |
| 重复内容会自动处罚 | 通常是规范选择和抓取效率问题，不等于人工处罚；抄袭和规模化滥用另论 | 风险说明 |
| canonical 是命令 | canonical 是强信号但非绝对命令；重定向、内链、sitemap 和内容一致性要协同 | 建议 |
| canonical 必须构建期生成 | 最终可抓取 HTML/HTTP header 正确且稳定即可；构建期只是某些静态站的工程选择 | 项目实现 |
| 分页都 canonical 到第一页 | 错。可索引分页通常自引用 canonical，并提供可抓取链接；不要把独特商品页都并到第一页 | 技术建议 |
| 所有资源必须自托管 | 不是 SEO 规则。按性能、隐私、可靠性和 CSP 权衡，Shopify CDN/必要三方服务可以合理使用 | 项目门禁 |
| inline script 会伤排名 | 不是直接 SEO 规则；它影响 CSP、安全、缓存或主线程时才需治理 | 安全/性能 |
| URL 必须尾斜杠且最多三级 | 选择一种一致格式即可；层级应服务用户和维护，不是固定排名阈值 | 项目门禁 |
| sitemap 会让页面收录 | sitemap 是发现和规范弱信号，不保证抓取、索引或排名 | 提示 |
| robots.txt 能移除已索引 URL | robots 控制抓取；被阻止 URL 仍可能无内容地出现在索引。移除需用 noindex（允许抓取）、认证、删除或移除工具 | 要求 |
| 结构化数据会直接提排名 | 它帮助理解并提供富结果资格，不保证展示或通用排名提升 | 资格 |
| Organization + WebSite 每页必须有 | 不是 Google 要求；放在最相关页面并保持一致即可，避免无意义重复和错误数据 | 建议 |
| `knowsAbout` 会直接让 LLM 推荐品牌 | 没有可靠证据证明直接因果；可用于准确实体描述，但只能作为实验 | 实验 |
| DA/DR 是 Google 排名指标 | 是第三方估算，只能做相对研究，不能当搜索引擎事实 | 工具指标 |
| 301 会损失 PageRank | Google 官方说明永久重定向不会因此损失 PageRank；错误映射、链路和内容变化仍会造成风险 | A 级事实 |

遇到“必须”时，先问：是抓取/索引要求、富结果资格、官方建议、无障碍/安全要求、团队预算，还是未经验证的行业习惯。

明确规则：全站统一添加 `nofollow` 不要做，链接属性必须按普通编辑、赞助和 UGC 的真实关系选择。
