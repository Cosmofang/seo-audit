# 信息架构与内部链接

目标是让用户和爬虫通过清晰路径理解“有哪些页面、彼此什么关系、哪些最重要”。URL 看起来短不等于架构好；导航、页面类型、链接图和内容边界更重要。

## 设计原则

- 从用户任务和实体关系建树：主页 -> 核心类别/服务 -> 子类/主题 -> 详情。
- 为每种模板定义唯一职责，避免首页、collection、产品页、指南争夺同一主意图。
- 重要页面应从导航、分类或相关内容获得普通 HTML 链接，不依赖站内搜索或 JS 点击事件。
- 点击深度是诊断指标，不是固定“三次以内”排名规则。高价值页应更容易到达。
- 面包屑表达真实层级；可见面包屑与 `BreadcrumbList` 保持一致。

## 内链系统

四类链接各司其职：

1. 全局导航：稳定核心类别和商业页。
2. 层级链接：父类、子类、面包屑、分页。
3. 上下文链接：在正文中连接定义、证据、教程和下一步商业页。
4. 相关模块：相关产品/文章，规则要相关且可控，不能成为全站垃圾链接。

锚文本要描述目标页面，不需要全部精确匹配；同一目标可自然变化。链接放在用户真正需要进一步信息的位置。不要通过大量页脚关键词链接或隐藏链接塑造权重。

## 发现问题

- 孤儿页：sitemap/分析/GSC 中存在，但 crawl 无入链。
- 近孤儿页：只有 sitemap、分页深处或一个弱链接。
- 断链与链式重定向：更新到最终 200 URL。
- 过度链接：模板给每页加数百个不相关链接，稀释使用价值和 crawl 信号。
- 死胡同：详情页没有返回类别、相关内容或下一步。
- 链接到非规范 URL：参数、HTTP、旧域、错误斜杠、重定向地址。

## Hub 与主题集群

Hub 应帮助导航和决策，不能只是链接列表。支持页解决不同子任务，互相链接只在有上下文时进行。一个主题拥有很多页面不等于“权威”；覆盖质量、实体信誉、原创经验和外部认可更关键。

## 分页与无限滚动

- 分页页有独立可抓取 URL 和普通 `<a href>`，每页自引用 canonical。
- 不要把第 2 页以后 canonical 到第 1 页，也不要只靠滚动事件暴露内容。
- 详情页应能从分页/分类路径被发现；sitemap 是补充，不替代链接。
- `view-all` 只有在性能和用户体验允许且确实包含全部内容时才适合作为替代。

## 架构变更验收

比较变更前后：可索引 URL 数、每模板入链数、点击深度、孤儿页、重定向、canonical、分页可发现性、高价值页面 crawl 频率和转化路径。大规模改 URL 视为迁站，使用迁站 playbook。
