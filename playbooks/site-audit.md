# 全站 SEO 审计 SOP

## 1. 定义范围

记录域名/子域、环境、市场、语言、CMS、页面类型、业务目标、重点目录、访问权限、数据周期和已知迁移。审计前先确认是否授权抓取生产站及速率限制。

## 2. 收集证据

- crawl：HTML 与需要时的 JS render；状态、指令、canonical、hreflang、标题、内容、链接、分页、schema。
- GSC/Bing：queries/pages、索引、sitemap、CWV、增强结果、人工处置。
- 分析/商业：landing page、转化、收入、库存、利润、季节性。
- 日志/CDN：爬虫命中、5xx、参数浪费、响应时间。
- SERP/竞品：意图、页面类型、功能、品牌和内容/链接差距。
- 人工模板检查：移动端、主流程、隐私/同意、可见内容、事实准确性。

本仓脚本是补充信号：

```bash
node scripts/audit-seo.mjs --dir dist --expected-origin https://www.example.com
node scripts/audit-live.mjs https://www.example.com
```

它们不能替代完整 crawl、render、GSC、日志、链接或收入审计。

## 3. 验证关键路径

按模板抽样：主页、类别、详情、内容、分页、参数、语言、登录/搜索、404。验证“可发现 -> 可抓取 -> 可渲染 -> 可索引 -> canonical -> sitemap/内链一致”。

## 4. 分级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 | 阻止核心页面访问/索引或大规模错误 | 全站 noindex、错误域 canonical、5xx、迁站断链 |
| P1 | 明确影响高价值页面或大量模板 | 商品不可发现、hreflang 集群错误、严重 CWV |
| P2 | 增长和质量机会 | CTR、内链、内容差距、schema 资格 |
| P3 | 实验/低影响/项目偏好 | llms.txt、非关键格式统一、软预算 |

每项写：事实、证据等级、影响 URL/模板、用户/业务影响、建议、负责人、依赖、工作量、验收命令/指标。不要把同一问题按 URL 重复几千行，应归纳根因与样本。

## 5. 形成路线图

先 P0/P1，再 quick wins 和增长。区分技术、内容、设计、业务、平台边界；把“必须”和“建议”分开。与 owner 确认可能改变 URL、索引、模板或跟踪的高风险操作。

## 6. 实施与复验

- 先记录基线和回滚方案。
- 在 staging/小样本测试，再部署。
- 复跑 crawl、脚本、schema、CWV 和业务流程。
- 部署后检查实际 edge 响应，不只检查源代码。
- 设置观察窗和告警；关闭问题必须附证据。

## 审计报告最小结构

1. 业务目标与范围。
2. 执行摘要：最大风险、最大机会、90 天路线图。
3. 数据与方法限制。
4. 按 P0-P3 的发现和修复。
5. 页面类型/主题表现。
6. KPI 基线、owner、时间表和验收。
